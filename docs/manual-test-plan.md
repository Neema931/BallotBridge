# Ballot Bridge manual test plan

## Test setup

1. Create the database with `database/schema.sql` and configure the MySQL credentials in `config/database.php`. For an existing installation, run all applicable migrations in README order, including `database/migration_election_setup_wizard.sql`, `database/migration_candidate_ballot_builder.sql`, `database/migration_election_settings.sql`, `database/migration_audit_ledger.sql`, `database/migration_election_results.sql`, `database/migration_voter_credentials.sql`, `database/migration_candidate_dashboard.sql`, and `database/migration_candidate_application_source.sql`.
2. Replace the seed admin placeholder with a hash generated by PHP's `password_hash()`.
3. Register a voter, then apply as a candidate at `candidate/register.php` for a Draft or scheduled election with an open candidate position. Approve/reject the voter and review the candidate application from the admin area. Configure a test mail transport and sender before testing review email delivery.
4. Create a draft election with a future schedule, add positions, assign registered candidate accounts from Manage candidates, then approve their applications.
5. To test voting, set the election's start/end times and IANA timezone to include the current time, then open it or enable automatic launch and run the scheduler. Keep separate accounts for voter, candidate, and administrator checks.
6. In production, set `APP_ERROR_LOG` to a writable log file outside the web root; otherwise PHP uses the server's configured error log.

| Test case | Steps | Expected result |
|---|---|---|
| Voter registration | Submit registration with a unique name, email, registration number, matching valid password, and the voter role. | Account and voter profile are created; the default account status is pending and the user is told approval is required. |
| Candidate self-nomination | Open `candidate/register.php` with a Draft and a scheduled election accepting nominations. Submit a unique identity, position, password confirmation, optional campaign details/photo, and eligibility certification. | Eligible positions are grouped by election; candidate account and application are created as pending and linked to the selected election/position; a confirmation notice appears on the login screen. |
| Candidate nominations closed | Visit `candidate/register.php` with no Draft/upcoming election accepting nominations; repeat with a past nomination deadline and with only referendum positions. | The page displays “Nominations Currently Closed,” disables all application controls, and direct POST submissions cannot create an account or candidate row. |
| Candidate application identity and validation | Try a duplicate email or ID number, invalid position ID, missing eligibility checkbox, invalid email, mismatched/short password, oversized slogan/manifesto, and invalid/oversized photo. | Invalid applications create no user or candidate row; duplicate identities are blocked; server validation matches the form limits and valid JPG/PNG uploads are linked to the pending application. |
| Invalid registration | Try a malformed email, missing registration number, short/mismatched password, invalid role submitted by editing the request, and duplicate email or registration number. | Registration is rejected; no account is created for invalid or duplicate data. |
| Login with active account | Log in with an active account for each role. | User is redirected to the matching admin, candidate, or voter dashboard and the session ID changes. |
| Login with invalid or inactive account | Try a wrong password, pending account, and suspended account. | A generic login failure is shown; the user is not authenticated. Repeated failures trigger the session throttle. |
| Candidate portal login | Sign in at `candidate/login.php` using an active candidate's email and then their registration ID; also try a voter, pending candidate, and ambiguous email/ID match. | Only one active candidate account with valid credentials is accepted; `$_SESSION['candidate_id']` and the shared user session are set, and the candidate dashboard opens. Invalid attempts show a generic alert and use the login throttle. |
| Candidate remember-me | Sign in with and without “Remember me,” then inspect the session and remember cookies and test idle expiry in a controlled environment. | Checked sessions use the remembered lifetime; unchecked sessions retain the normal session lifetime; logout clears both cookies. |
| Candidate password help | Open “Forgot Password?” with and without a configured election support email. | The page provides the configured support mail link or clearly tells the candidate how to contact the election administrator. |
| Candidate login notices | Submit a valid candidate application and log out from the candidate portal. | Registration confirmation and sign-out notices appear inline on `candidate/login.php`. |
| Login password visibility | On the login page, enter a password and toggle the eye control twice. | The control switches between password/text visibility, updates its accessible label and pressed state, and does not submit the form. |
| Login page layout | Open the login page. | The page shows the login form without the site footer or guest registration links. |
| Logout | Use the Logout button, then open a protected URL in the same browser. | Session is destroyed and the protected page redirects to login. A GET request to the logout URL does not log the user out. |
| Session cookie flags | Log in over HTTPS and inspect the session cookie in browser developer tools. | Cookie is HttpOnly, SameSite=Lax, Secure under HTTPS, and scoped to the app path. |
| Session timeout | Log in, wait longer than `SESSION_LIFETIME` without making a request, then open a protected page. | The old session is discarded and the user is redirected to login. |
| Role-boundary checks | While logged in as each role, directly request pages belonging to the other two roles, including a POST action endpoint. | Access is denied or redirected; no protected data is returned and no action is performed. |
| CSRF and output escaping | Submit a state-changing form with its CSRF token removed or altered; enter HTML markup as a name or manifesto and inspect its rendered page. | Invalid tokens receive HTTP 403 with a generic message; submitted markup is displayed as text, not executed. |
| Admin dashboard | Open the admin dashboard. | Voter, candidate, election, and vote totals are displayed. |
| Admin election management | Create and edit a draft election and positions; try invalid dates; open it, close it, and try deleting elections with and without recorded votes. | Valid draft changes save; invalid schedules are rejected; only permitted lifecycle actions succeed; elections with votes cannot be deleted. |
| Admin election settings | Select draft and scheduled elections; edit title, voter instructions, support email, schedule/timezone, optional nomination deadline, voting system, abstentions, and verification methods. Change a field and revert it; submit an invalid email, malformed schedule, invalid timezone, nomination deadline after poll opening, and tampered voting method. | The sticky save bar appears only while values differ from their initial state; valid changes persist, support email appears on voter ballots, nomination deadline can be left blank or saved on/before opening, invalid values are rejected, and each actual save is recorded in Audit logs. |
| Settings live lock | Open an election and wait until it is within its voting window, then try changing general information, schedule, or voting rules through the UI and a direct POST. Repeat after recording a ballot and while paused/closed. | Fields and save action are read-only after voting begins or ballot activity exists; server-side checks reject tampered requests. |
| Settings lifecycle controls | Launch a draft with a contest, pause a live election, resume before closing time, and close polls early. Cancel each confirmation modal before confirming. | Each lifecycle change requires confirmation, valid transitions succeed, cancelled actions do nothing, and successful transitions are audited. |
| Settings danger zone | Try resetting votes on a non-draft election; reset test ballots in a draft; try deleting elections with open/paused status, ballot activity, a wrong confirmation title, and a valid no-ballot draft. | Reset is available only in Draft and clears votes plus ballot submissions; deletion requires the exact title, rejects open/paused elections and ballot activity, and successful resets/deletions are audited. |
| Election setup wizard | Save a complete draft with each voting system, timezone, optional nomination deadline, verification methods, abstention choice, and logo; save with an invalid date order, nomination deadline after opening, or invalid logo; use the create-and-add-candidates action. | Valid settings persist; blank or valid nomination deadlines persist and display in the selected timezone; invalid submissions are rejected; the primary action redirects to Manage candidates with the election selected. |
| Admin ballot builder | In a draft election, create and edit candidate positions and referendum contests; assign registered candidate accounts; add/edit referendum choices; approve/reject pending candidate applications; toggle randomized order and preview the ballot. Try duplicate accounts, mismatched positions, invalid uploads, and changing contest type while entries exist. | Entries are saved to the selected election and contest, candidate accounts remain reviewable, referendum options are shown without candidate accounts, and randomized ordering affects the voter-facing ballot only. Invalid or duplicate assignments are rejected. |
| Candidate vetting tabs and notifications | Create self-registered and administrator-assigned pending candidates, approve one, reject another with feedback, and disqualify an approved candidate. Configure the mail transport to succeed and then fail. | Pending Approval counts self-nominations separately; the queue shows applicant identity/profile and a manifesto dialog; approval adds the candidate to Approved Ballot and emails confirmation; rejection/disqualification requires feedback, moves the candidate to Rejected, and emails that feedback. Mail delivery failure is reported without rolling back the recorded decision. |
| Candidate vetting locks | Open Pending Approval and Approved Ballot for live, paused, and closed elections; try review, disqualification, profile, position, randomization, and manual-add actions in the UI and with direct POST requests. | Ballot changes and candidate decisions are disabled in the UI and rejected server-side once the election is locked; ballot preview remains available. |
| Ballot-builder election lock | Open an election while it is live, paused, or closed; try editing contests, profiles, options, randomization, and candidate review through both the UI and a direct POST. Repeat before the election opens. | Live, paused, and closed ballots are read-only on the page and server. Draft and scheduled elections remain editable until a ballot is submitted for a contest. |
| Ballot-builder deletion guard | Submit a ballot or abstention for a contest, then try to remove an entry or delete that contest. Repeat on a contest with no submissions. | Submitted ballot data prevents changes or deletion, including abstained submissions; unused contests and entries can be removed and their uploaded photos are cleaned up. |
| Automatic scheduling | Enable auto-launch for a draft with a position, set a start time near the present, and run `tools/activate_scheduled_elections.php`; repeat after the end time. | The election opens at/after start, closes after end, and each transition has an audit entry; drafts without auto-launch remain drafts. |
| Admin audit logs | Create/edit/open/close/delete a draft election or position; add/update/review a voter; review a candidate; then open Audit logs. Search by keyword, admin, category, and UTC date range; inspect View Details; export CSV and open the print/PDF report. | Rows include UTC timestamps, actor name and role, severity badge, description, IP, and available JSON before/after data. Filters apply to both exports, old entries without captured snapshots say so, CSV cells are safe to open in spreadsheet software, and PDF output includes all matching entries. |
| Audit ledger immutability | Attempt UPDATE and DELETE against a disposable audit row in a test database; submit failed sign-ins until the login throttle is reached. | Database triggers reject audit-row UPDATE and DELETE. Failed sign-in and throttling events appear under Security Alerts without recording passwords or submitted email addresses. |
| Admin voter review | Register a voter, open Manage voters, and approve a pending registration; repeat with another voter, set a custom rejection reason, then reject them. | Status tabs show correct counts, pending registrations show name, ID, email, timestamp, and review actions. Approval activates eligibility and sends an approval email. Rejection confirms the selected applicant, saves the reason, and sends it in the rejection email. Both decisions require CSRF-protected POSTs. |
| Admin voter email retry | Make the configured mail transport fail, review a pending voter, restore the transport, then retry the failed email from the voter list. | The review decision is retained, failed delivery is clearly shown, and retry sends the matching approval/rejection email and marks it sent. |
| Admin add voter | Add a voter manually with unique valid details and a valid initial password; then try a duplicate email or registration number. | A valid account and voter profile are created as pending. Duplicate details are rejected. The password is not emailed and must be shared securely. |
| Admin voter CSV import | Import a UTF-8 CSV with `full_name,email,reg_number` and optional `phone`; include invalid rows, duplicates, malformed headers, an oversized file, and more than 500 rows. | Valid rows create pending accounts, each receives a one-time password setup email, invalid/duplicate rows are reported without rolling back valid imports, malformed/oversized files are rejected, and processing is capped at 500 rows. |
| Voter one-time password setup | Use a CSV setup link or request Resend voting credentials for an eligible voter. Set a valid password, then try the same link again, an expired link, a tampered token, and a suspended account's token. | Only valid, unexpired, unused links for pending or active voter accounts set a password; links are stored as hashes, expire after 30 minutes, are consumed once, and never permit suspended/rejected accounts to reset. |
| Admin edit voter | Change a voter's name, email, registration number, and phone; then try changing to another account's email or registration number. | Valid details are saved to both user and voter records; duplicate details are rejected without partial updates. |
| Admin voter access and anonymous participation | Search by voter name, ID, or email; select an election and filter approved voters by Voted/Not voted; revoke access and restore a suspended voter. Inspect SQL calls/page source to ensure results are not joined. | Search and filters return matching users; participation shows only ballot submission state for the selected election and never candidate choices. Revocation retains ballot records and only valid status transitions work through CSRF-protected POSTs. |
| Admin results privacy and publication | Open a Live, Paused, Draft, and Scheduled election with test ballots; inspect the page source and attempt `?export=csv` directly. Then close an election and open See results. After closure, suspend or add a voter and revisit the report. | Before status is Closed, no candidate totals, turnout counts, candidate results, or CSV data are returned; the lock screen shows status/countdown and refreshes until closure. After closure, the official report shows eligible voters, distinct ballots cast, turnout, abstentions, position cards in ballot order, candidate photos/affiliations, aggregate counts, percentages, and declared winners. New closures retain the eligible-voter count from closure even if account statuses later change. Legacy closed elections without snapshots clearly state that current active-roster counts are used. CSV has only aggregate data; print/PDF includes all official results. |
| Results arithmetic and ties | View candidate and referendum contests under FPTP and multiple selection, then test ranked ballots with transfers, exhausted ballots, and a final tie. Include a multi-selection contest with a tie at the final available selection. | Percentages use the contest's total votes/selections (ranked results show first preferences plus IRV rounds); multiple-selection winners respect the configured selection limit, tied seats are not falsely awarded, and a final ranked tie has no invented winner. |
| Candidate dashboard | Log in as candidates with pending, rejected, and approved applications. Test draft, scheduled, live, paused, and closed elections; use multiple applications, a missing photo/slogan/manifesto, and a configured nomination deadline. | The database-backed application banner and feedback are correct; election status and countdown reflect schedule/state; ballot preview, milestones, and readiness checklist match saved data; profile editing is disabled after voting begins; vote totals are never displayed. |
| Candidate My Profile | Open My Profile for an assigned application. Check the breadcrumb, headshot preview, readonly name/position, affiliation, slogan, manifesto counter, account email, and sticky save bar. Upload valid JPG/PNG, then try SVG, renamed non-image, and oversized files. | Preview updates immediately for valid images; invalid files are rejected client- and server-side; name/position cannot be changed; profile data saves and the resulting ballot matches it. |
| My Profile account security | Change contact email and password separately and together. Try a duplicate email, omit/wrong current password, submit mismatched or too-short passwords, and save unchanged account details. | Valid changes persist; credentials changes require the current password; duplicates and invalid passwords are rejected without partial changes; email-only or password-only updates do not alter ballot application status. |
| My Profile election locks | Try profile edits in Draft, Scheduled, at/after the nomination freeze, Live, Paused, and Closed states; submit a direct POST after the freeze. While locked, update email/password separately. | Public ballot controls are disabled at/after the freeze and once voting starts/pauses/closes; server-side validation rejects tampered profile updates; account security remains available. |
| Candidate rejection and resubmission | Reject a pending application with specific feedback; sign in as the candidate, review the feedback, edit public profile details before freeze, and save. Then review the resubmitted application. | Rejection feedback persists, the candidate account stays active, a changed public profile clears feedback and returns the application to pending review, and an administrator can review it again. |
| Voter dashboard | Log in as an active voter and open the dashboard with an open election. Repeat with a pending or suspended voter and with a partial ballot. | Active voter sees schedule-aware availability and per-position progress; inactive voter cannot proceed; completed ballots cannot be resubmitted. |
| FPTP ballot | Open a First-Past-the-Post ballot with candidate and referendum contests; try to review without choosing, then select one option for each. | Each open contest requires exactly one approved candidate or referendum option, or permitted abstention; review lists the selected labels and contests. |
| Multiple-selection ballot | Choose up to the configured per-contest maximum on candidate and referendum contests; try exceeding it, submitting none, and choosing both options and abstention. | Valid selections are accepted; too many, empty, mixed, or unauthorized abstentions are rejected by client and server validation. |
| Ranked-choice ballot | Assign unique ranks to candidates and referendum choices, submit a partial ranking, then tamper with duplicate ranks or entry IDs. | Rankings are stored with rank order; duplicate ranks and invalid entries are rejected; results use instant-runoff transfers. |
| Voter verification | Test email-token send/resend throttling, expiry, attempt limits, and valid verification; test Voter ID + account password with valid and invalid credentials; test both methods together. | Only selected methods are required and all selected methods must pass; SMS remains unavailable; no ballot is recorded after failed verification. |
| Abstentions | In each voting system, abstain on one permitted position and vote on another; try an abstention when the election prohibits it. | Abstention completes only that position, is recorded once, is not counted as a candidate vote, and is reflected in results and receipts. |
| Empty/partial ballot | Open an election with a position that has no approved candidates, or with a position the voter has already voted for. | Empty positions are unavailable; previously voted positions are marked and omitted from required choices; remaining eligible positions can still be voted. |
| Election window and status | Try the ballot before its start, after its end, after it is closed, and while it is open and in range. | Only an open election within its date range accepts votes. |
| Tampered ballot | POST an invalid election ID, an unknown position, a candidate from another position/election, a rejected candidate, or malformed nested selection data. | Request is rejected; no votes are committed. |
| Two-tab double-vote race | Open the same ballot in two tabs for the same voter. Submit both as close together as possible; repeat with two browser sessions for the same voter if available. | At most one submission succeeds for each voter/position. The other receives an already-recorded/refresh message; database vote counts contain no duplicate voter-position row. |
| Repeat submission | After a successful ballot, refresh or resubmit the old ballot. | Previously recorded positions cannot receive another vote; already-voted positions plus remaining positions behave correctly. |
| Receipt privacy | After voting or abstaining, open My voting receipts and inspect the page and its HTML. | Receipt shows election, submission time, completed positions, and abstention count, but never candidate selections. |
| Error response privacy | Cause a controlled database or file operation failure in a test environment and inspect the browser response. | Browser receives a generic error without SQL text, filesystem paths, or stack traces; diagnostic details are written only to the configured server error log. |
